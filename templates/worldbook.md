# 世界书生成指令

## 你的任务

根据作品需要，构建一份世界书。

**核心原则：世界书不是百科全书，是"故事需要 AI 知道的一切"。**

不同故事需要的世界信息完全不同。一个发生在咖啡馆里的恋爱故事可能只需要一段关于这家店的描述；一个架空帝国的权谋故事可能需要几千字的政治体系和历史。你的工作是判断——这个故事需要 AI 了解哪些背景才能写好？然后只写那些。

### 格式与文件

- 采用 XYAML（XML+YAML 混合格式），所有条目包裹在 `<lore_codex name="作品名">` 容器内
- XML 标签名用具体名称（如 `<frozen_tundra>`、`<merchant_code>`），不用 `<topic>` 或 `<entry>`
- YAML 字段名根据内容自行发明，不必拘泥于示例
- 文件保存至作品目录，命名：`世界书.xyaml`
- 输出不包含注释
- 若用户另有特殊指示，以用户要求为准

### 条目元数据（必须）

每个条目的第一行必须包含以下元数据字段，用于控制条目在 SillyTavern 中的激活行为：

```yaml
  _activation: blue          # blue=蓝灯(常量/始终激活) 或 green=绿灯(关键词触发)
  _keys: 关键词1, 关键词2    # 绿灯条目的触发关键词（蓝灯条目可省略）
  _position: before_char     # 插入位置：before_char / after_char / D4 / D3 / D2 / D1 / D0
  _order: 100                # 可选，插入顺序（越大越靠下），默认按条目序号
```

### 激活策略选择指南

根据条目内容类型选择合适的激活策略：

**蓝灯（constant/始终激活）— 用于 AI 必须始终知道的核心信息：**
- 世界观/时代背景/核心前提
- 力量体系/核心规则（如魔法限制、科技水平）
- 社会禁忌/通用法则
- 主角核心设定（如果只有一个主角）

**绿灯（selective/关键词触发）— 用于按需加载的内容：**
- NPC/配角描述 → 关键词填角色名+别称，position 用 `after_char`
- 地点/场所 → 关键词填地名+别名
- 物品/道具 → 关键词填物品名
- 势力/组织 → 关键词填组织名+缩写
- 特定事件/剧情节点 → 关键词填触发词

**位置选择：**
- `before_char`：大多数世界观、规则、设定类条目（放在角色定义之前，更权威）
- `after_char`：NPC 描述、补充细节（放在角色定义之后）
- `D4`~`D0`：需要 AI 格外注意的信息放深度条目（D0最底部=最强效果），但不要滥用

**进阶技巧（可选，适合高级用户）：**
- 可为同一角色创建一个"激活条目"（蓝灯/绿灯，内容含角色名），用递归激活该角色的其他绿灯条目
- 绿灯关键词支持正则表达式：`/正则/` 格式，如 `/好感度:\s*[3-9]\d/` 匹配好感度30+
- 提示词模板插件支持 EJS 条件控制：`<% if (condition) { %>...内容...<% } %>`
- 酒馆助手脚本可通过 `injectPrompts` 动态注入提示词

## EJS 动态内容（进阶）

当角色卡使用了变量系统（MVU）时，世界书条目可以利用 EJS 模板语法实现动态内容。

### 使用场景
- 根据好感度/信任度等变量显示不同的角色态度
- 根据剧情阶段显示不同的世界设定
- 条件性展示隐藏信息

### 语法示例

```xyaml
<character_reaction>
  _activation: green
  _keys: 角色名
  _position: after_char
  
  <% if (getvar('好感度') >= 50) { %>
  态度: 温柔亲近，主动找话题
  称呼: 用昵称称呼玩家
  <% } else { %>
  态度: 礼貌但保持距离
  称呼: 用敬称
  <% } %>
</character_reaction>
```

### 多阶段示例

```xyaml
<world_state>
  _activation: green
  _keys: 世界状态, 当前局势
  _position: before_char

  <% var phase = Number(getvar('剧情阶段') || 1); %>
  <% if (phase <= 2) { %>
  当前局势: 表面和平，暗流涌动
  可探索区域: 城镇中心、市集、酒馆
  <% } else if (phase <= 4) { %>
  当前局势: 冲突爆发，各方势力公开对抗
  可探索区域: 城镇中心、地下通道、前线营地
  <% } else { %>
  当前局势: 决战在即，世界格局即将改变
  可探索区域: 所有区域解锁，包括禁地
  <% } %>
</world_state>
```

### 何时使用 EJS
- **用**：角色卡有 MVU 变量系统、需要阶段性变化的内容
- **不用**：简单卡、没有变量系统的卡、纯背景设定

### 注意事项
- `getvar('变量名')` 返回字符串，需要比较数值时用 `Number()` 转换
- EJS 代码不会被 AI "看到"，只有满足条件的部分才会出现在实际 prompt 中
- 不要过度使用——大多数条目用固定内容就够了，只在"需要根据状态变化"时才用 EJS

## 创作思路

### 第一步：问自己"AI 不知道这个会写错什么？"

世界书里的每一条信息都应该通过这个测试：如果 AI 不知道这个设定，它在续写故事时会犯什么错误？

- 会用错科技水平？→ 需要写技术/时代背景
- 会搞混势力关系？→ 需要写政治/阵营设定
- 会让角色做出不合理的选择？→ 需要写社会规则/禁忌
- 会让超自然能力变得没有限制？→ 需要写力量体系的边界

如果删掉某条信息 AI 也不会写错——那这条可能不需要。

### 第二步：选择要写的内容类型

以下是世界书中常见的内容类型。**不要逐个填写**——根据故事需要挑选。

**空间类** — 故事发生在什么样的地方
- 城市、村庄、建筑、自然区域
- 地图上的重要位置
- 地方特色（气候、文化氛围、危险程度）

**规则类** — 这个世界运行的逻辑
- 超自然/科幻力量体系（原理、限制、代价）
- 社会制度（权力结构、阶层、法律）
- 经济逻辑（货币、贸易、稀缺资源）
- 游戏机制（如果是游戏向：属性、技能、成长系统）

**时间线类** — 到达当下的过程
- 重大历史事件
- 角色前史
- 当前局势的成因

**百科类** — 杂项知识
- 种族/物种设定
- 物品/道具/武器
- 组织/势力档案
- 术语表

### 第三步：决定每条内容的详略

同一部世界书里，不同条目的详细程度可以天差地别：

- **一句话够用就写一句话**："这个世界没有枪械。冷兵器和魔法是唯一的战斗手段。"
- **需要结构化就用结构化**：一个有多个流派和限制条件的力量体系，用嵌套 YAML 组织更清晰
- **需要叙事感就用叙事段落**：一段历史、一个传说，用故事化的文字比干巴巴的条目更容易让 AI 吸收

### 第四步：输出 XYAML

把所有条目放进 `<lore_codex>` 容器。每个条目用一个有意义的 XML 标签包裹。标签名和字段名都由你根据内容决定。

## 创作范例

### 范例一：一个只需要一页纸的世界书

故事是现代都市背景的悬疑剧，发生在一栋老公寓楼里。不需要宏大世界观，但需要 AI 知道这栋楼的情况。

```xml
<lore_codex name="永安里24号">

<the_building name="永安里24号">
  _activation: blue
  _position: before_char

  概况: |
    建于1988年的六层砖混住宅楼，没有电梯。位于城市老城区，周围是菜市场、五金店和一家开了二十年的兰州拉面馆。
    楼里一共24户，实际住着不到一半——年轻人都搬走了，剩下的多是老人和租户。

  关键信息:
    走廊: 声控灯经常坏。三楼到四楼的拐角有一面裂开的穿衣镜，没人知道谁放的，也没人搬走。
    地下室: 名义上是储物间，实际已经荒废。铁门能打开但灯不亮。
    天台: 没有锁，但上去需要经过六楼最东边那户人家的门口——那户人家白天从不开门。

  居民备忘:
    - 三楼东户: 刘婆婆，独居，耳背，但什么风吹草动都瞒不过她
    - 五楼西户: 空置半年了。上一个租户走得很突然，东西都没搬完
</the_building>

</lore_codex>
```

### 范例二：一个需要多层结构的世界书

故事是架空世界的冒险题材，有力量体系和势力设定。

```xml
<lore_codex name="裂隙纪元">

<era_overview name="当前纪元">
  _activation: blue
  _position: before_char

  时代背景: |
    "大裂隙"发生在四十年前——天空裂开了一道缝，持续了七天。裂隙关闭后，世界上出现了两样之前不存在的东西：回声石，和能使用回声石的人。
    四十年后的现在，回声石已经深度嵌入社会运作。有人用它照明、通讯、治病；有人用它杀人。围绕回声石的开采和分配，三个主要势力形成了脆弱的平衡。
</era_overview>

<echo_stone name="回声石">
  _activation: green
  _keys: 回声石, 调谐者, 调谐, echo stone
  _position: before_char

  本质: |
    一种半透明的矿石，内部有微弱的光脉波动。只在大裂隙遗址附近的地层中出产。

  使用方式: |
    大约7%的人天生能"听到"回声石内部的频率。这些人被称为"调谐者"。调谐者通过接触回声石并在心中构建特定的意象，可以将石头中储存的能量以不同形式释放。

  限制——这很重要:
    - 回声石是消耗品。一块石头的能量用完就变成普通石头
    - 调谐者过度使用会出现"回声残留"——在耳中持续听到低频嗡鸣，严重时导致失聪和精神崩溃
    - 每个调谐者只能掌握一种释放形式（光、热、动力、感知中的一种），终生不变
    - 非调谐者接触回声石没有任何效果，也没有任何危险
</echo_stone>

<three_powers name="三方势力">
  _activation: green
  _keys: 联合开采局, 游隼商会, 沉默教团, 三方势力
  _position: before_char

  概述: |
    围绕回声石的控制权，形成了三个势力。它们之间不是简单的好人坏人关系——每一方都有自己的逻辑。

  联合开采局:
    性质: 官方机构，垄断回声石的开采和分配
    立场: 认为回声石是危险资源，必须由政府统一管控
    问题: 腐败严重，高层中有人在黑市上倒卖配额

  游隼商会:
    性质: 由走私者和独立调谐者组成的松散联盟
    立场: 反对垄断，主张回声石自由流通
    问题: 内部派系复杂，部分成员只是披着理想主义外衣的毒贩

  沉默教团:
    性质: 宗教组织，信徒认为大裂隙是"警示"
    立场: 主张销毁所有回声石，回到裂隙前的世界
    问题: 越来越激进，近期发生过针对矿场的袭击事件
</three_powers>

</lore_codex>
```

### 范例三：世界书条目可以是任何东西

不要被"标准分类"限制想象力。下面是一些不那么常见但可能对故事很有用的条目类型：

```xml
/* 一首民谣——让 AI 知道这个世界的文化氛围 */
<folk_song name="矿工谣">
  _activation: green
  _keys: 矿工, 矿区, 采矿, 矿工谣
  _position: before_char

  歌词节选: |
    石头底下有石头，石头底下有骨头。
    挖到银子给老板，挖到骨头带回家。
  流传范围: 北部矿区，矿工在下井前唱
  AI 须知: 如果角色来自矿区或提到采矿，可以自然地引用这首歌
</folk_song>

/* 一份物价表——让 AI 知道这个世界的经济水平 */
<price_reference name="裂隙纪元物价">
  _activation: blue
  _position: before_char

  日常参考:
    - 一顿普通饭菜: 5-8 铜板
    - 一晚最便宜的旅馆: 20 铜板
    - 一名雇佣兵一天的佣金: 3-5 银币（1银币 = 100铜板）
    - 一块拇指大小的回声石: 10-50 金币（看品质），黑市价格翻倍
  AI 须知: 请在涉及交易场景时参考此表，避免出现物价不合理的情况
</price_reference>

/* 一条禁忌——让 AI 知道角色不能随便做什么 */
<social_taboo name="不能做的事">
  _activation: blue
  _position: before_char

  在联合开采局管辖区内:
    - 私藏回声石（超过3块）是重罪，最高判处15年
    - 调谐者如果未在官方登记，一经发现强制收编
    - 在公共场合展示调谐能力会引起恐慌——普通人对调谐者又依赖又恐惧
</social_taboo>
```

## 最后检查

写完之后回头扫一遍：

- 每条信息都能通过"AI 不知道这个会写错什么"的测试吗？通不过的删掉
- 有没有写了大段设定但故事里其实用不到的内容？有的话考虑精简
- 条目之间有没有矛盾？（比如一处说回声石无害，另一处说它有辐射）
- 字段名和标签名读起来直观吗？另一个人看到能立刻理解是什么意思吗？
